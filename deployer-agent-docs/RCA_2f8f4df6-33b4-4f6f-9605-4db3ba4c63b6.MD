# RCA — Deployment failed at pull_source (milano-execution-p4)

## Summary
The initial deploy of `milano-execution-p4` (FARM template `fastapi_react_mongo_shadcn_base_image`) fails at the **pull_source** step, before any image build. The pipeline cannot regenerate the backend dependency file because the backend source directory is missing from the app.

## Exact error (identical on two runs)
```
pull_source: activity error (type: v3.InitialDeploy.PullSource):
prepare build context: update python dependencies: write requirements.txt:
open /tmp/agent-env-.../app/backend/requirements.txt: no such file or directory
(type: PathError)
```

## Evidence
- Run `2a634f13-a468-44dd-8217-37907b30ec40` — failed at pull_source with the error above.
- Run `2f8f4df6-33b4-4f6f-9605-4db3ba4c63b6` — a fresh retry with `force_repull=true` failed **identically**, confirming the fault is persistent, not transient.
- `wakeup_environment` succeeded on both runs → the preview pod/platform is healthy; the problem is the copied source layout.
- Eph sandbox could not be spawned (`eph_source_access_failed`) because pull_source fails before it uploads the source archive, so there is no archive to inspect.

## Root cause
During pull_source the platform copies `/app` from the preview pod and then regenerates `backend/requirements.txt`. The write fails with `no such file or directory` because **`/app/backend/` does not exist** in the project. The FARM template requires a Python backend at `/app/backend/` (with `requirements.txt` and `server.py`). The backend folder is either missing, empty, or named differently (e.g. `api/`, `server/`, or files placed directly under `/app`).

## Fix (E1 / source)
1. Ensure the backend lives at `/app/backend/` in the preview workspace.
2. Ensure `/app/backend/requirements.txt` exists (even if minimal — the pipeline rewrites/augments it, but the file+directory must be present for the write to land).
3. Confirm the FARM layout: `/app/backend/server.py` (FastAPI app) and `/app/frontend/` (React) both present.
4. Redeploy once the backend directory is in place.

## Not the cause
- Not a manifest issue — pull_source runs before build_image and is independent of the Dockerfile/nginx/config manifest set.
- Not a secret/env issue.
- Not infra/platform — preview pod wakeup succeeded; failure is deterministic and tied to missing source directory.
