# RCA — Deploy blocked at trigger_indie (insufficient credits)

## Summary
The deploy could not start. The `trigger_indie` step rejected the run at the
billing gate because the account does not have enough credits to cover this
deployment.

## Evidence
trigger_indie returned (non-retryable):
```
{"error":{"kind":"insufficient_credits",
  "message":"Not enough credits. Required: 50, Available: 5.077261075903967",
  "details":{"available":5.077261075903967,"required":50},
  "retryable":false}}
```
- Required: **50 ECU**
- Available: **5.077 ECU** (shortfall ~44.9 ECU)
- `retryable: false` — the pipeline will reject any resume until the balance is topped up.

Deployment: `milano-execution-p4` (e2022ad0-8d9f-4aeb-95c2-2a05ed01d568),
type=initial, tier_0, template fastapi_react_mongo_shadcn_base_image.

## Root cause
Account credit balance (5.077 ECU) is below the 50 ECU required to run this
initial deployment. This is an account/billing state, not a code, manifest,
secret, or infrastructure fault. The UI deploy-panel confirmation covers ECU
cost acknowledgement but does not add balance.

## Fix (user action required)
Top up the account credit balance to at least the required 50 ECU (settle any
negative/lapsed balance), then retry the deploy. No code or manifest change is
needed.

## Note
I did NOT call resume_pipeline — the gate is non-retryable and the balance is
unchanged, so a resume would fail identically. Separately, the two earlier runs
(2f8f4df6, 2a634f13) had failed during build context with a missing
`backend/requirements.txt`; once credits are restored, that source issue may
surface and should be re-evaluated on the next run.
