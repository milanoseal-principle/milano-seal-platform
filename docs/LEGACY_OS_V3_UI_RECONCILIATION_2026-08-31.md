## Net-new design principles worth preserving

### 1. Situation-first client mirroring

The legacy `Is this you?` section expresses a useful conversion principle: before presenting service architecture, mirror recognizable client situations so a visitor can self-identify quickly.

Canonical reuse rule:

- Use only as an optional content pattern inside existing public architecture.
- Do not create a second homepage journey.
- Situations must route into existing Global Document Intelligence, professional, pricing, or Secure Intake surfaces.
- Never use a situation card to make a compliance conclusion.

### 2. Warm authority before procedural complexity

The source intentionally combines human/founder trust with institutional execution cues. This remains useful as a design principle:

- Human trust may appear before deeper process detail.
- Founder presence should support confidence, not dominate the platform.
- Institutional authority and Matter clarity remain primary.
- Current `/founder`, `/about`, and the homepage Founder Trust Anchor already implement the stronger production version.

### 3. Editorial asymmetry

The legacy layout uses asymmetric image/copy compositions rather than repeated equal cards. Preserve this only as a visual rhythm principle for high-value public surfaces where it improves hierarchy.

Do not import its exact CSS, fonts, gradients, diagonal clip-path hero, fixed widths, or standalone media-query system into production.

### 4. Process as one continuous rail

The legacy four-stage process communicates continuity better than isolated boxes.

Canonical production principle:

`Matter review → quote/payment → execution → authentication/apostille where applicable → custody/release → delivery/close`

Any visual rail must read canonical Matter truth and must not create alternate states.

### 5. Quiet service differentiation

The source differentiates Signature / Priority / Executive through coordination level rather than commodity notarization count. This remains aligned with current production pricing doctrine.

Current production pricing page controls all public wording and does not publish stale static amounts from this file.
